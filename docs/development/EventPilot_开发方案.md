# EventPilot 活动领航系统 Web 应用开发方案

## 系统核心价值与设计灵魂

EventPilot 是活动承办团队的"数字大脑"，通过**流程引擎**（固化最佳实践）与**复盘引擎**（沉淀经验教训）的双轮驱动，实现活动交付的标准化、可控化与持续进化。其设计灵魂在于以"活动项目"为中心的信息聚合，将内部协同平台的外部专业能力体现完美融合，确保每次活动交付精善尽美，并让团队专业能力可持续积累和复用。

---

## 第一部分：产品定义与核心价值

### 1. 产品愿景

成为活动承办团队的"数字大脑"和智能领航系统，确保每次活动交付"精善尽美"，并让团队专业能力可持续积累和复用，构建专业服务壁垒。

### 2. 设计理念

**以活动项目为中心的信息聚合**
所有数据、任务、文件、沟通都围绕"活动项目"这一核心实体展开，实现信息的集中化和可追溯性。

**双轮驱动架构**
- **流程引擎**：固化最佳实践，将成功经验标准化、工具化
- **复盘引擎**：沉淀经验教训，构建知识库，推动持续进化

**内外兼修的系统设计**
- **对内协同作战平台**：高效的任务协作、信息同步、进度管控
- **对外专业能力体现**：标准化的交付流程、专业化的服务文档

### 3. 核心价值

**对负责人：全局掌控与数据驱动**
- **全局视图掌控进度**：通过仪表盘实时掌握项目状态、资源分配、风险预警
- **沉淀标准化流程**：将成功经验转化为可复用的流程模板和知识库
- **数据驱动复盘优化**：通过数据化指标找出可改进点，持续优化服务质量

**对团队：清晰透明的协作体验**
- **任务清晰透明**：每个人都知道自己要做什么、什么时间完成、依赖什么
- **协作信息同步及时**：减少沟通成本，避免信息孤岛，降低失误率
- **移动端友好**：现场执行人员可随时查看任务、上传核验结果

**对业务：可靠性与专业形象提升**
- **提升交付可靠性**：标准化流程减少人为失误，确保交付质量一致性
- **提高客户满意度**：专业的交付记录和复盘报告展示团队实力
- **构建专业服务壁垒**：持续积累的经验和知识库形成核心竞争力

## 第二部分：功能架构蓝图

### 模块一：策划与启动中心

#### 1.1 智能方案生成
**核心功能：**
- 基于活动类型（培训、沙龙、年会等）的模板管理
- 模板参数化：支持可变参数（时间、地点、预算上限等）
- 一键生成《活动执行方案》：包含任务分解、时间线、资源需求表
- 方案版本管理：支持版本对比和回滚

**解决的业务问题：**
- 每次活动需要从零开始制定方案，浪费时间和经验
- 方案标准化程度低，容易遗漏关键环节
- 无法快速复用历史成功经验

**技术要点：**
- 方案模板作为配置文件存储，支持版本控制
- 基于模板参数的动态渲染引擎
- 方案导出为PDF/Word格式便于客户确认

#### 1.2 结构化预算看板
**核心功能：**
- 预算科目管理：支持自定义预算分类结构
- 实时对比"预估 vs 实际"：动态计算预算偏差
- 高亮预警机制：超过预算阈值自动标记和通知
- 预算明细记录：每一笔支出关联到具体费用项

**解决的业务问题：**
- 预算控制依赖Excel，无法实时更新
- 预算偏差发现不及时，难以做决策调整
- 历史预算数据不便于分析和参考

**技术要点：**
- 预算数据模型支持多级科目树结构
- 实时计算引擎处理预算对比和偏差分析
- 基于阈值的预警触发机制

#### 1.3 关联方档案库
**核心功能：**
- 多类型档案管理：讲师、场地、供应商、客户联系人
- 永久档案：记录基本信息、合作历史、关键事件
- 风险标注：支持"注意事项"、"优先级"等标签
- 档案关联：在活动中快速选择历史关联方

**解决的业务问题：**
- 关联方信息散落在各处，难以管理
- 历史合作经验无法有效利用
- 新成员难以快速了解关键关联方情况

**技术要点：**
- 统一的档案数据模型，支持类型扩展
- 档案与活动的关联查询和检索
- 标签系统支持灵活的风险标注

### 模块二：执行与协同中心

#### 2.1 可视化流程看板
**核心功能：**
- 多视图支持：甘特图（时间视角）与看板视图（状态视角）
- 多线任务管理：策划线、嘉宾线、物料线、场地线、宣传线、现场线、复盘线
- 任务依赖关系支持：定义前置任务和后续任务
- 状态自动流转：完成任务自动触发后续任务

**解决的业务问题：**
- 任务进度可视化程度低，难以捕捉风险
- 多线任务管理混乱，容易遗漏关键节点
- 依赖关系不明确，导致等待和延期

**技术要点：**
- 任务数据模型支持依赖图结构
- 甘特图渲染引擎处理时间轴和任务块
- 看板拖拽交互与状态同步

#### 2.2 结构化沟通任务
**核心功能：**
- 结构化沟通任务：将关键沟通作为任务，明确"沟通什么、和谁沟通、目标是什么"
- 强制闭环机制：沟通任务必须关联结论性文件或证据
- 聊天记录整合：支持微信聊天截图上传并关联至任务
- 机器人提醒：支持关键任务更新发送微信提醒

**解决的业务问题：**
- 关键沟通没有留下书面记录，易产生歧义
- 聊天记录散落在各处，难以追溯
- 重要信息容易遗漏或遗忘

**技术要点：**
- 沟通任务模型明确"输入-过程-输出"结构
- 文件上传和关联存储
- 微信Webhook集成实现消息推送

#### 2.3 物料与清单管理
**核心功能：**
- 清单模板化：将"心中清单"数字化，支持创建可复用模板
- 状态追踪：每项物料标记状态（未准备、准备中、待确认、已完成）
- 责任人分配：明确每项物料的负责人和完成时间
- 核验关联：现场核验时快速引用清单

**解决的业务问题：**
- 物料准备依赖个人经验，不便于团队协作
- 没有统一的状态追踪，容易遗漏
- 新人难以快速了解物料准备要求

**技术要点：**
- 物料清单的模板引擎和实例化机制
- 状态机和权限控制
- 文件关联支持上传图片、文档等核验证据

### 模块三：现场执行中心

#### 3.1 移动端核验清单
**核心功能：**
- 离线操作支持：基于确认需求生成可离线操作的检查清单
- 极简交互：勾选完成、拍照上传、文字备注
- 自动报告：核验完成后自动生成《核验报告》
- 位置和时间戳：自动记录核验位置和时间

**解决的业务问题：**
- 现场核验依赖纸质清单，不便于数据化
- 核验结果无法实时上传，影响问题响应速度
- 核验记录难以追溯和分析

**技术要点：**
- PWA（渐进式Web应用）支持离线功能
- Service Worker缓存机制
- 本地数据库和场景同步策略

#### 3.2 简易现场工具
**核心功能：**
- 签到二维码：生成活动签到二维码，支持扫码签到
- 电子调查问卷：发布实时调查问卷，收集参与者反馈
- 快速拍照：支持快速拍照上传，关联到具体任务

**解决的业务问题：**
- 现场签到依赖纸质表格，数据难以数字化
- 反馈收集不即时，无法现场调整
- 现场证据难以及时记录和上传

**技术要点：**
- 二维码生成和解析引擎
- 实时表单提交和数据聚合
- 相机API集成和图片压缩优化

#### 3.3 应急指南
**核心功能：**
- 应急联系表：配置每场活动的专属应急联系人
- 应急预案展示：分类展示不同场景的应急预案
- 一键呼叫：点击电话号码直接拨打电话

**解决的业务问题：**
- 应急信息分散存储，紧急时难以快速找到
- 新成员不了解应急流程
- 无法快速联系到关键责任人

**技术要点：**
- 应急数据模型的配置化存储
- 移动端优化的显示和交互
- 原生API集成（拨号、地图等）

### 模块四：复盘与进化中心

#### 4.1 结构化复盘模板
**核心功能：**
- 多维度复盘引导：目标达成、流程执行、成本控制、客户反馈、团队协作
- 自动关联本次活动问题：从任务、物料、沟通等模块自动提取问题点
- 结构化记录：按维度记录成功经验、待改进项、改进建议
- 复盘报告导出：导出标准化的复盘报告

**解决的业务问题：**
- 复盘依赖个人记忆，容易遗漏关键点
- 没有标准化的复盘流程，复盘质量不一致
- 复盘结果难以有效利用和传承

**技术要点：**
- 复盘模板的定义和动态渲染引擎
- 数据关联逻辑自动提取问题点
- 文档生成和导出引擎

#### 4.2 问题与经验知识库
**核心功能：**
- 智能转化：复盘"待改进项"自动转为知识条目并打标签
- 知识推流：创建新活动时，系统智能推送相关历史问题
- 多维度检索：按标签、活动类型、时间等维度检索知识
- 经验复用：支持将成功经验标记为"最佳实践"

**解决的业务问题：**
- 遇到的问题重复发生，无法有效传承经验
- 知识沉淀后无人查阅，难以发挥作用
- 缺乏有效的知识推荐机制

**技术要点：**
- 知识图谱构建：问题-标签-活动的关联关系
- 推荐算法：基于活动特征的智能知识推送
- 全文搜索和过滤查询优化

#### 4.3 活动数据仪表盘 ✅ 已实现
**核心功能：**
- 跨活动核心指标：预算偏差率、任务完成率、问题发生率、客户满意度
- 趋势分析：展示指标随时间的变化趋势
- 对比分析：支持不同活动类型、不同负责人的指标对比
- 异常检测：自动识别异常模式并提醒

**实现的API端点：**
- `GET /api/events/dashboard_analytics/` - 活动数据分析仪表盘
  - 总体统计（活动数、任务数、完成率、预算）
  - 状态分布、类型分布、任务类型分布
  - 月度趋势（近12个月）
  - 高风险活动列表
  - 即将到期活动
  - TOP活跃负责人

**实现的页面：**
- `frontend/src/views/Analytics.vue` - 活动数据分析页面
  - 4个核心指标卡片
  - 多个统计表格（状态/类型/任务分布）
  - 高风险活动和即将到期列表
  - TOP负责人排名
  - 月度趋势表格
  - 日期范围筛选

**解决的业务问题：**
- 无法量化评估团队和服务质量
- 难以发现系统性问题和改进方向
- 缺乏数据支持来做决策

**技术要点：**
- 数据仓库和聚合查询优化
- 可视化图表库集成
- 统计分析和异常检测算法

## 第三部分：设计风格与交互要求

### 3.1 设计原则

**专业优先设计**
- 界面以工具效率为核心，避免娱乐化设计元素
- 信息密度合理，重点突出，减少视觉干扰
- 专业的工作流设计，符合活动承办团队的思维模式

**视觉主题融入**
- 融入"舵轮"、"仪表盘"等"领航"元素
- 使用专业的色彩体系（深蓝、海军蓝、蓝灰色系）
- 图标和图标系统专业且一致

### 3.2 关键交互设计

#### 3.2.1 微信整合
**设计目标：**
- 将微信作为工作沟通的天然补充，而非重复界面
- 关键信息在微信中可接收，详细操作回系统中完成

**交互特性：**
- 聊天记录截图上传：支持将微信聊天记录截图上传并关联至具体任务
- 微信提醒配置：关键任务更新可配置微信机器人提醒
- 快捷访问：微信通知中包含深度链接，点击可直接跳转到系统对应页面

**技术实现：**
- 微信企业号机器人API集成
- 移动端应用支持深度链接

#### 3.2.2 清单驱动交互
**设计目标：**
- 核心操作以"勾选完成"为主，追求极简交互
- 降低操作门槛，适合现场快速执行

**交互特性：**
- 勾选即完成：只需一次点击即可标记完成，减少操作步骤
- 视觉反馈：完成后立即显示视觉反馈（颜色变化、对勾动画）
- 快速备注：提供快捷入口添加文字备注或拍照

**技术实现：**
- 移动端优化的触控交互
- 本地化操作优先，后台异步同步

#### 3.2.3 全局搜索
**设计目标：**
- 快速找到所需信息，减少导航层次

**交互特性：**
- 统一搜索入口：从任何页面都可触发全局搜索
- 智能搜索：支持关键词、拼音、首字母搜索
- 分类显示：搜索结果按活动、联系人、文件、历史问题分类展示

**技术实现：**
- 全文搜索引擎集成（Elasticsearch）
- 搜索结果聚合和相关性排序算法

#### 3.2.4 移动端适配
**设计目标：**
- 核心功能在移动设备上有良好的可用性
- 支持添加到桌面，提供类似App的体验

**交互特性：**
- 响应式设计：自适应不同屏幕尺寸
- 关键功能优先：在有限屏幕上优先展示最关键的信息和操作
- 触控友好：按钮和交互区域适合触控操作

**技术实现：**
- 响应式CSS框架（TailwindCSS）
- PWA技术：支持离线、添加到主屏幕
- 性能优化：减少网络请求，优化加载速度

## 第四部分：技术方案与实施路线

### 4.1 技术栈详解

#### 4.1.1 前端技术栈

**核心框架：Vue 3 + TypeScript**
- **选择理由：** Vue 3提供渐进式开发体验，TypeScript提供类型安全
- **主要依赖：**
  - Vue Router：页面路由管理
  - Pinia：状态管理
  - VueUse：组合式工具库
  - TailwindCSS：实用优先的CSS框架
  - Element Plus：UI组件库（适用于企业级应用）

**API集成：React Query + OpenAPI生成**
- **React Query：** 处理数据获取、缓存、更新和错误处理
- **OpenAPI生成：** 从后端OpenAPI规范自动生成TypeScript类型和API客户端

**PWA支持：**
- **Vite PWA插件：** 提供Service Worker和离线支持
- **IndexedDB：** 本地数据存储（核验清单等）

#### 4.1.2 后端技术栈

**核心框架：Django 5 + Django REST Framework**
- **选择理由：** Django提供完整的ORM、Admin认证等基础设施，DRF提供强大的API开发能力
- **主要特性：**
  - Django ORM：数据模型和数据库操作
  - Django REST Framework：RESTful API开发和认证
  - Django Guardian：对象级权限控制
  - Celery：异步任务队列（通知、邮件等）

**数据库：PostgreSQL 15**
- **选择理由：** 支持复杂查询、事务、全文搜索，适合企业级应用
- **优化特性：**
  - 连接池：PgBouncer用于连接池管理
  - 索引策略：为常用查询建立合适索引

**缓存：Redis**
- **用途：** 会话存储、缓存、实时消息队列

#### 4.1.3 部署架构

**容器化部署：Docker + Docker Compose**
- **容器化：** 所有服务容器化，便于部署和扩展
- **编排：** Docker Compose用于开发和部署环境

**云平台支持：**
- **支持平台：** 腾讯云、阿里云等主流云平台
- **推荐配置：** 2核4G起步，根据并发量扩展

**CDN和静态资源：**
- **CDN：** 使用CDN加速静态资源加载
- **对象存储：** 对象存储用于文件上传和存储

### 4.2 非功能性需求

#### 4.2.1 权限控制（RBAC）
**角色定义：**
- **系统管理员：** 全局管理权限，包括用户管理、系统配置
- **项目负责人：** 项目的完全控制权限（创建、编辑、分配、删除）
- **执行成员：** 分配任务的执行权限，可更新任务状态、上传文件
- **只读观察者：** 只读权限，可查看项目信息但不能修改

**数据权限：**
- **项目级权限：** 用户只能访问被授权的项目
- **字段级权限：** 敏感字段（如精确预算）需要特定权限才能查看
- **操作审计：** 所有写操作记录日志，支持追溯

**技术实现：**
- Django Guardian提供对象级权限
- 自定义中间件处理权限检查
- PostgreSQL Row Level Security（可选）

#### 4.2.2 数据安全
**加密存储：**
- **敏感数据：** 密码、API密钥等使用加密存储（bcrypt/Argon2）
- **传输加密：** 全站HTTPS，TLS 1.3

**操作日志：**
- **完整性：** 所有写操作记录创建人、时间、IP、操作内容
- **可追溯：** 支持按用户、时间、操作类型查询
- **保存周期：** 重要日志保存3年，一般日志保存1年

**备份策略：**
- **频率：** 数据库每日全量备份，每小时增量备份
- **保留：** 保留最近30天备份，保留每月备份1年
- **验证：** 定期验证备份可恢复性

#### 4.2.3 性能要求
**响应时间：**
- **核心列表页：** 加载时间 < 2秒
- **复杂操作：** 响应时间 < 3秒
- **移动端页面：** 首次灰度渲染 < 1.5秒

**并发支持：**
- **目标：** 支持100+并发用户同时操作
- **优化：** 数据库连接池、缓存策略、异步处理

**监控和告警：**
- **APM：** 使用APM工具（如Sentry）监控性能和错误
- **告警：** 错误率、响应时间、数据库连接数异常时告警

## 第五部分：详细技术实现要点

### 5.1 数据库核心模型设计

#### 5.1.1 活动项目核心表

**events（活动表）**
```
- id: UUID主键
- name: 活动名称
- type: 活动类型（培训/沙龙/年会等）
- start_date, end_date: 活动时间
- client: 客户信息
- status: 活动状态（策划中/执行中/已完成/已复盘）
- owner_id: 项目负责人ID
- created_at, updated_at: 时间戳
```

**tasks（任务表）**
```
- id: UUID主键
- event_id: 关联活动ID
- title: 任务标题
- description: 任务描述
- assignee_id: 负责人ID
- status: 任务状态
- due_date: 截止日期
- dependencies: 任务依赖关系（JSON数组）
- task_type: 任务类型（策划/嘉宾/物料/现场等）
- created_at, updated_at: 时间戳
```

**profiles（关联方档案表）**
```
- id: UUID主键
- profile_type: 档案类型（讲师/场地/供应商/联系人）
- name: 名称
- contact_info: 联系信息（JSON）
- cooperation_history: 合作历史（文本）
- notes: 注意事项（文本）
- tags: 标签（JSON数组）
- created_at, updated_at: 时间戳
```

**knowledge_entries（知识条目表）**
```
- id: UUID主键
- entry_type: 条目类型（问题/经验/最佳实践）
- content: 内容（富文本）
- tags: 标签（JSON数组）
- related_events: 关联活动ID（JSON数组）
- created_by: 创建人ID
- created_at, updated_at: 时间戳
```

### 5.2 API设计原则

#### 5.2.1 统一响应格式
```json
{
  "data": { /* 实际数据 */ },
  "meta": {

  }
```

```json

    }
  }

```

#### 5.2.3 分页和过滤
```
GET /api/events?page=1&page_size=20&status=active&sort=start_date
```

### 5.3 安全和合规

#### 5.3.1 认证流程
- **Access Token:** 15分钟有效期，存储在内存
- **Refresh Token:** 7天有效期，存储在httpOnly Cookie
- **自动刷新:** API客户端检测401错误自动刷新

#### 5.3.2 权限检查
- **Django Guardian:** 对象级权限控制
- **自定义权限装饰器:** @has_permission(event, 'write')
- **Row Level Security:** 数据库层面保护敏感数据

### 5.4 移动端优化

#### 5.4.1 性能优化
- **代码分割:** 按路由懒加载
- **资源压缩:** 图片压缩、JS/CSS压缩
- **CDN加速:** 静态资源使用CDN

#### 5.4.2 离线支持
- **Service Worker:** 缓存关键页面和数据
- **IndexedDB:** 本地存储核验清单数据
- **后台同步:** 网络恢复后自动同步本地数据

## 第七部分：风险和挑战

### 7.1 技术风险

**复杂权限系统**
- **风险：** 对象级权限控制实现复杂，容易出错
- **缓解：** 先实现项目级权限，再逐步细化；使用成熟的权限系统（Django Guardian）

**移动端性能**
- **风险：** 移动设备性能差异大，复杂页面响应慢
- **缓解：** 保守的性能优化策略（懒加载、虚拟滚动）；限制移动端功能复杂度

**数据一致性**
- **风险：** 离线操作导致数据一致性问题
- **缓解：** 实现冲突检测和解决机制；关键数据采用server-first策略

### 7.2 业务风险

**用户习惯改变**
- **风险：** 用户习惯现有流程，不愿意改变工作方式
- **缓解：** 分阶段推广，先在重点项目试点；收集反馈持续改进

**功能需求蔓延**
- **风险：** 功能越加越多，偏离核心价值
- **缓解：** 严格的需求评审和优先级控制；定期回顾核心价值

### 7.3 项目风险

**时间投入不足**
- **风险：** 开发团队时间投入不足，项目延期
- **缓解：** 合理的项目规划和里程碑；及时调整范围

**人才能力不足**
- **风险：** 团队成员技术能力不足，影响质量和效率
- **缓解：** 技术评审和培训；合理的技术选型和架构设计
