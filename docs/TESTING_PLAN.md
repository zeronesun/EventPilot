## 1. 测试方案概述

### 1.1 目标

建立系统化的测试体系，确保 EventPilot 项目的代码质量和功能稳定性。

### 1.2 适用范围

本方案适用于 EventPilot 项目的所有测试活动，包括但不限于：
- 前端 Vue 3 应用测试
- 后端 Django API 测试
- WebSocket 实时通信测试
- 集成测试和端到端测试

### 1.3 测试原则

- **自动化优先**: 优先编写自动化测试
- **持续集成**: 每次提交都要运行测试
- **快速反馈**: 失败的测试要快速定位问题
- **可维护性**: 测试代码应该清晰易懂
- **覆盖率目标**: 核心模块 75% 以上

## 2. 测试类型

### 2.1 单元测试 (Unit Tests)

**目标**: 验证单个函数、组件或类的正确性

#### 前端单元测试

**技术栈**: Vitest + @vue/test-utils

**覆盖范围**:
- 工具函数 (`utils/`)
- 可组合函数 (`composables/`)
- 组件渲染逻辑
- API 客户端 (`api/`)
- 状态管理 (`stores/`)

**命名规范**:
```
*.test.ts - 测试文件
*.spec.ts - 规范文件（可选）
```

**执行频率**:
- 开发时：实时运行（watch 模式）
- 提交前：必须通过
- CI/CD：每次运行

#### 后端单元测试

**技术栈**: Pytest

**覆盖范围**:
- 模型方法 (`models/`)
- 序列化器 (`serializers/`)
- 业务逻辑 (`services/`)
- 工具函数 (`utils/`)
- 中间件 (`middleware/`)

**命名规范**:
```
tests/test_*.py - 模块测试
tests/apps/*/tests/test_*.py - 应用测试
```

**执行频率**:
- 开发时：按需运行
- 提交前：必须通过
- CI/CD：每次运行

---

### 2.2 集成测试 (Integration Tests)

**目标**: 验证多个模块之间的交互是否正常

**测试场景**:

- 跨模块的数据流转
- 权限和认证流程
- 错误处理和异常情况

**执行环境**:
- 使用测试数据库
- 模拟外部服务依赖
- 独立于生产环境

#### 前端集成测试

**测试场景**:
- 组件之间的交互
- 路由导航
- 状态管理流程
- API 调用和响应处理

## 3. 测试环境

### 3.1 环境配置

#### 开发环境
- **数据库**: 开发数据库（可重置）
- **配置**: DEBUG=True
- **日志级别**: DEBUG
- **外部服务**: 模拟或沙盒环境

#### 测试环境
- **数据库**: 临时测试数据库
- **配置**: DEBUG=False
- **日志级别**: INFO/ERROR
- **外部服务**: 测试账号或模拟服务

#### CI/CD 环境
- **数据库**: 内存数据库（SQLite）
- **配置**: DEBUG=False
- **日志级别**: WARNING/ERROR
- **外部服务**: 严格模拟

### 3.2 测试数据

**数据来源**:
- Faker 库生成测试数据
- 固定的测试fixtures
- 少量生产数据脱敏样本

**数据清理**:
- 每次测试前清空数据库
- 使用事务回滚机制
- 隔离的测试数据空间

## 4. 测试执行流程

### 4.1 开发时测试

```bash
# 前端 - 实时监视模式
npm run test

# 后端 - 指定模块
pytest tests/test_specific_module.py -v

# 完整套件
npm run test:run
pytest tests/ -v
```

### 4.2 提交前测试

```bash
# 前端 - 运行所有测试
npm run test:run

# 后端 - 运行所有测试
pytest tests/ -v

# 检查覆盖率
npm run test:coverage
```

### 4.3 CI/CD 集成

**触发条件**:
- 每次提交到主分支
- 每次创建 Pull Request
- 定时任务（每晚运行）

**执行步骤**:
1. 安装依赖
2. 运行 linting 检查
3. 运行所有测试
4. 生成覆盖率报告
5. 构建生产版本

**失败处理**:
- 阻止 merge
- 发送通知
- 生成失败报告

## 5. 测试报告

### 5.1 报告类型

#### 前端测试报告

**内容**:
- 测试通过率
- 测试耗时
- 覆盖率统计
- 失败测试详情

**查看方式**:
```bash

npm run test:run

# 可视化报告
npm run test:ui
```

**内容**:
- 测试通过率
- 每个测试的结果
- 警告信息
- 耗时统计

**查看方式**:
```bash
pytest tests/ -v --tb=short
```

```bash
# 前端

# 后端
```

- HTML: `coverage/` 或 `htmlcov/`

## 10. 常见问题处理

### 10.1 测试不稳定（Flaky Tests）

**原因**:
- 依赖外部服务
- 时序问题
- 环境差异

**解决**:
- 使用 mock/stub
- 增加重试机制
- 固定测试数据

### 10.2 测试太慢

**优化策略**:
- 限制数据库查询
- 使用内存数据库
- 并行执行测试
- 跳过不必要的操作

### 10.3 覆盖率不达标

**提升方案**:
- 识别未覆盖的关键路径
- 补充测试用例
- 重构难以测试的代码
- 考虑测试难度和收益
