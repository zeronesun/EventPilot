# EventPilot 技术架构深度分析

## 一、技术栈选型深度评估

### 1.1 前端技术栈：Vue 3 + TypeScript

#### 选择依据分析

**Vue 3 的优势：**
- **渐进式框架：** 与React相比，Vue更适合渐进式开发，可以从简单的组件逐步构建复杂应用
- **Composition API：** 更好的TypeScript支持，便于逻辑复用和代码组织
- **生态成熟：** Vue Router、Pinia、VueUse等核心库稳定可靠
- **团队学习曲线：** 对于有React经验的团队，Vue 3的学习成本相对较低

**TypeScript的价值：**
- **类型安全：** 在编译时捕获错误，减少运行时问题
- **IDE支持：** 更好的代码补全和重构能力
- **大型项目维护性：** 类型系统有助于代码理解和长期维护

#### 技术风险与缓解

**风险1：Vue 3 生态系统相对React较小**
- **缓解：** 核心功能使用成熟库，复杂功能自研；关键依赖定期评估和升级计划

**风险2：TypeScript初学者的学习成本**
- **缓解：** 采用渐进式类型策略，优先对核心模块进行类型化，逐步扩展

### 1.2 后端技术栈：Django 5 + DRF

#### 选择依据分析

**Django的优势：**
- **完整的生态系统：** ORM、Admin、认证、中间件等开箱即用
- **快速开发：** 特别适合MVP阶段的快速迭代
- **成熟稳定：** Django有超过15年的发展历史，稳定性高
- **Admin后台：** Django Admin可以快速搭建管理后台，节省开发时间

**Django REST Framework (DRF)的优势：**
- **强大的序列化：** 自动处理复杂对象序列化
- **可浏览的API：** 自动生成的可浏览API界面，便于调试
- **认证和权限系统：** 内置多种认证方式和细粒度权限控制
- **分页和过滤：** 内置的分页和过滤功能减少重复开发

#### 技术风险与缓解

**风险1：Django单体架构的扩展性限制**
- **缓解：** 采用良好的架构分层，为未来微服务化预留接口；使用Celery异步处理重负载任务

**风险2：ORM性能瓶颈**
- **缓解：** 复杂查询使用原生SQL；关键查询建立索引；使用select_related/prefetch_related优化关联查询

### 1.3 数据库：PostgreSQL

#### 选择依据分析

**PostgreSQL的优势：**
- **复杂查询能力：** 支持窗口函数、CTE、全文搜索等高级功能
- **事务完整性：** 完全符合ACID标准，适合金融级应用
- **JSON支持：** 原生支持JSON类型，便于存储灵活的数据结构
- **扩展性：** 支持多种扩展（如PostGIS空间扩展、全文搜索等）

#### 技术风险与缓解

**风险1：PostgreSQL在高并发场景下的性能**
- **缓解：** 使用连接池（PgBouncer）；优化查询和索引；分区表策略

**风险2：数据库扩展成本**
- **缓解：** 设计良好的分库分表策略；读写分离架构（主从复制）

## 二、关键技术挑战深度分析

### 2.1 任务依赖关系图的实现

#### 业务需求
系统需要支持任务之间的依赖关系，一个任务可能依赖于多个前置任务，完成后才能开始。

#### 技术方案比较

**方案A：数据库关系建模**
```python
# 简单的依赖关系表
class TaskDependency(models.Model):
    task = models.ForeignKey('Task', on_delete=models.CASCADE, related_name='dependencies')
    depends_on = models.ForeignKey('Task', on_delete=models.CASCADE, related_name='dependents')
```

**方案B：图数据库引入**
- 使用Neo4j等图数据库专门处理复杂依赖关系
- 优势：原生支持图查询和算法
- 劣势：引入新的技术栈，增加复杂度和部署成本

#### 推荐方案：方案A + 应用层计算
**理由分析：**
1. **复杂度适中：** 任务依赖关系通常不会特别复杂（每个任务依赖的前置任务 ≤ 5个）
2. **性能可控：** 使用缓存和算法优化，可以满足性能要求
3. **技术栈统一：** 避免引入过多的技术栈

**具体实现：**
```python
def get_task_execution_order(event_id):
    """
    获取任务的执行顺序（拓扑排序）
    """
    tasks = Task.objects.filter(event_id=event_id)
    dependencies = TaskDependency.objects.filter(task__event_id=event_id)
    
    # 构建邻接表和入度计数
    in_degree = {task.id: 0 for task in tasks}
    graph = defaultdict(list)
    
    for dep in dependencies:
        graph[dep.depends_on.id].append(dep.task.id)
        in_degree[dep.task.id] += 1
    
    # Kahn算法进行拓扑排序
    queue = [task_id for task_id, degree in in_degree.items() if degree == 0]
    result = []
    
    while queue:
        node = queue.pop(0)
        result.append(node)
        
        for neighbor in graph[node]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)
    
    return result
```

### 2.2 移动端离线操作和数据同步

#### 业务需求
- 支持移动端离线核验清单操作
- 网络恢复后自动同步本地数据到服务器
- 处理数据冲突和一致性

#### 技术方案

**方案1：PWA + IndexedDB + 同步队列**
- **PWA技术：** Service Worker缓存关键页面和数据
- **IndexedDB：** 本地存储核验清单数据和操作队列
- **同步策略：** 网络恢复时将本地操作队列依次发送

**方案2：本地数据库 + 双向同步**
- 使用本地数据库（如SQLite）
- 实现完整的双向同步机制
- 处理冲突解决策略

#### 推荐方案：方案1（简化版）
**理由分析：**
1. **实现复杂度较低：** PWA技术成熟，IndexedDB浏览器原生支持
2. **适用场景：** 核验清单操作相对简单，主要是增加和状态更新
3. **冲突处理简单：** 按时间戳处理最后写入优先

**具体实现：**
```typescript
// 同步队列数据结构
interface SyncQueueItem {
  operation: 'create' | 'update' | 'delete';
  resource: 'checklist_item';
  resourceId: string;
  data: any;
  timestamp: number;
  status: 'pending' | 'synced' | 'failed' | 'conflict';
  retryCount: number;
}

class SyncQueue {
  private queue: Map<string, SyncQueueItem> = new Map();
  
  // 添加到同步队列
  async add(item: SyncQueueItem) {
    const id = item.resourceId;
    this.queue.set(id, item);
    await this.persistToIndexedDB();
    this.trySync();
  }
  
  // 尝试同步（网络可用时）
  async trySync() {
    if (!navigator.onLine) return;
    
    for (const [id, item] of this.queue.entries()) {
      if (item.status !== 'pending') continue;
      
      try {
        await this.syncItem(item);
        item.status = 'synced';
      } catch (error) {
        item.status = 'failed';
        if (item.retryCount > 3) {
          item.status = 'conflict'; // 需要手动解决
        }
      }
    }
    
    await this.persistToIndexedDB();
  }
  
  private async syncItem(item: SyncQueueItem) {
    switch (item.operation) {
      case 'create':
        await apiClient.post('/api/checklist_items', item.data);
        break;
      case 'update':
        await apiClient.put(`/api/checklist_items/${item.resourceId}`, item.data);
        break;
      case 'delete':
        await apiClient.delete(`/api/checklist_items/${item.resourceId}`);
        break;
    }
  }
}
```

### 2.3 知识图谱和智能推荐算法

#### 业务需求
- 复盘"待改进项"自动转为知识条目
- 创建新活动时，系统智能推送相关历史问题
- 支持多维度检索和推荐

#### 技术方案

**方案1：基于标签的简单推荐**
- 维护知识条目的标签体系
- 基于新活动的特征（类型、时间、负责人等）匹配标签
- 简单但有效的推荐策略

**方案2：基于内容的推荐（TF-IDF + 余弦相似度）**
- 对知识条目内容进行Text Analysis
- 计算TF-IDF向量和相似度
- 更智能的推荐但需要更多计算资源

**方案3：知识图谱 + 图算法**
- 构建完整的知识图谱实体关系
- 使用PageRank、协同过滤等图算法
- 最先进但复杂度最高

#### 推荐方案：方案2（平衡版）
**理由分析：**
1. **效果可控：** 基于内容的推荐算法成熟且有效
2. **资源合理：** 计算复杂度适中，可以实时计算
3. **可扩展：** 未来可以扩展为混合推荐（内容+协同过滤）

**具体实现（简化版TF-IDF）：**
```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

class KnowledgeRecommendationService:
    def __init__(self):
        self.vectorizer = TfidfVectorizer(stop_words='english')
        self.knowledge_vectors = None
        self.cache_timeout = 3600  # 1小时缓存
        self.last_cache_time = None
    
    def train(self, knowledge_entries):
        """
        训练推荐模型（定期更新）
        """
        content = [entry.content for entry in knowledge_entries]
        self.knowledge_vectors = self.vectorizer.fit_transform(content)
        self.last_cache_time = time.time()
    
    def recommend(self, event_data, top_k=5):
        """
        为活动推荐相关知识条目
        """
        # 构建查询向量（基于活动的类型、描述等）
        query_text = f"{event_data['type']} {event_data['description']}"
        query_vector = self.vectorizer.transform([query_text])
        
        # 计算相似度
        similarities = cosine_similarity(query_vector, self.knowledge_vectors).flatten()
        
        # 获取top-k最相关的条目
        top_indices = similarities.argsort()[-top_k:][::-1]
        return top_indices, similarities[top_indices]
    
    def should_retrain(self):
        """判断是否需要重新训练"""
        return (time.time() - self.last_cache_time) > self.cache_timeout
```

### 4.2 数据一致性挑战

#### 场景1：任务状态变更的级联更新
```
问题：当任务A标记为完成时，依赖A的任务B可能需要自动开始
```

**解决方案：使用事务 + 领域事件**
```python
from django.db import transaction
from django.dispatch import receiver
from django.db.models.signals import post_save

@receiver(post_save, sender=Task)
def handle_task_status_change(sender, instance, **kwargs):
    """
    处理任务状态变更
    """
    if instance.status == 'completed' and not kwargs.get('created'):
        # 查找依赖此任务的任务
        dependent_tasks = Task.objects.filter(
            dependencies__depends_on=instance,
            status='pending'
        )
        
        # 标记为可执行
        for task in dependent_tasks:
            task.status = 'ready'
            task.save()

def complete_task(task_id):
    """
    完成任务（确保事务完整性）
    """
    with transaction.atomic():
        task = Task.objects.select_for_update().get(id=task_id)
        task.status = 'completed'
        task.completed_at = timezone.now()
        task.save()
        
        # 信号会在此阶段触发，确保在同一事务中
```

问题：预算看板中的"预估vs实际"对比需要确保数据一致性

from django.db import transaction

@transaction.atomic(isolation='serializable')
def update_actual_budget(event_id, expense_data):
    """
    更新实际预算，使用可序列化隔离级别确保一致性
    """
    event = Event.objects.select_for_update().get(id=event_id)
    
    # 计算新的实际预算

        Expense.objects.filter(event=event).values_list('amount', flat=True)
    )
    
    # 更新预算偏差
    event.actual_budget = actual_budget
    event.budget_variance = event.estimated_budget - actual_budget
    
    event.save()

#### 现有方案的问题
当前方案中使用了JWT + refresh token，但存在一些潜在问题：
1. Refresh token存储在HTTP-only cookie中，移动端支持度可能不一致
2. JWT payload过大可能导致性能问题
3. Token撤销机制不够完善

**方案：分层级 + 无状态 + 缓存**

class PermissionLevel(Enum):
    # 资源级权限
    READ = 1
    WRITE = 2
    DELETE = 3
    ADMIN = 4

class Resource:
    EVENT = 'event'
    TASK = 'task'
    CHECKLIST = 'checklist'
    KNOWLEDGE = 'knowledge'
    PROFILE = 'profile'
    FILE = 'file'

class PermissionService:
    def check_permission(self, user, resource, resource_id, level):
        """
        检查用户对资源是否有指定权限
        """
        # 1. 基于角色的快速检查
        if self._has_global_permission(user, level):
            return True
        
        # 2. 资源级权限检查
        resource_access = ResourceAccess.objects.filter(
            user=user,
            resource_type=resource,
            resource_id=resource_id,
            permission_level__gte=level
        ).exists()
        
        if resource_access:
            return True
        
        # 3. 继承检查（如通过项目权限）
        if resource == Resource.TASK:
            task = Task.objects.get(id=resource_id)
            # 继承活动权限
            return self.check_permission(
                user, 
                Resource.EVENT, 
                task.event_id, 
                level
            )
        
        return False
    
    def grant_permission(self, user, resource, resource_id, level):
        """
        授予权限
        """
        ResourceAccess.objects.update_or_create(
            user=user,
            resource_type=resource,
            resource_id=resource_id,
            defaults={'permission_level': level}
        )
    
    def revoke_permission(self, user, resource, resource_id):
        """撤销权限"""
        ResourceAccess.objects.filter(
            user=user,
            resource_type=resource,
            resource_id=resource_id
        ).delete()
    
    def _has_global_permission(self, user, level):
        """检查全局权限"""
        user_role = UserRole.objects.get(user=user)
        role_permissions = RolePermission.objects.filter(
            role=user_role.role,
            permission_level__gte=level
        )
        return role_permissions.exists()

const CACHE_VERSION = 'v1';
const CACHE_DURATION = 24 * 60 * 60 * 1000; // 24小时

// 缓存策略配置
const CACHE_STRATEGY = {
  // 关键页面：网络优先，失败时使用缓存
  NETWORK_FIRST: [
    '/',
    '/mobile/tasks',
    '/mobile/checklist'
  ],
  
  // 静态资源：缓存优先
  CACHE_FIRST: [
    '/assets/',
    '/images/',
    '/fonts/'
  ],
  
  // API数据：网络优先，有缓存时快速返回
  STALE_WHILE_REVALIDATE: [
    '/api/events',
    '/api/tasks'
  ]
};

self.addEventListener('fetch', (event) => {
  const { pathname } = new URL(event.request.url);
  
  // 确定缓存策略
  let strategy = null;
  for (const [key, patterns] of Object.entries(CACHE_STRATEGY)) {
    if (patterns.some(pattern => pathname.startsWith(pattern))) {
      strategy = key;
      break;
    }
  }
  
  if (!strategy) {
    return; // 不处理其他请求
  }
  
  event.respondWith(handleRequest(event, strategy));
});

async function handleRequest(event: FetchEvent, strategy: string) {
  const cache = await caches.open(CACHE_VERSION);
  
  try {
    const networkResponse = await fetch(event.request);
    
    // 如果策略支持缓存，则更新缓存
    if (strategy === 'NETWORK_FIRST' || strategy === 'STALE_WHILE_REVALIDATE') {
      cache.put(event.request, networkResponse.clone());
    }
    
    return networkResponse;
  } catch (error) {
    // 网络失败，尝试使用缓存
    const cachedResponse = await cache.match(event.request);
    if (cachedResponse) {
      return cachedResponse;
    }
    throw error;
  }
}

// 定期清理过期缓存
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames.map((cacheName) => {
          if (cacheName !== CACHE_VERSION) {
            return caches.delete(cacheName);
          }
        })
      );
    })
  );
});

          store.createIndex('status', 'status', { unique: false });
        }
      };
    });
  }
  
  // 批量插入优化
  async batchInsert(storeName: string, items: any[]) {
    const transaction = this.db!.transaction([storeName], 'readwrite');
    const store = transaction.objectStore(storeName);
    
    // 使用雪崩防护（限制并发数量）
    const BATCH_SIZE = 50;
    for (let i = 0; i < items.length; i += BATCH_SIZE) {
      const batch = items.slice(i, i + BATCH_SIZE);
      await new Promise<void>((resolve) => {
        const promises = batch.map(item => new Promise<void>((resolve) => {
          const request = store.add(item);
          request.onsuccess = () => resolve();
        }));
        Promise.all(promises).then(() => resolve());
      });
    }
    
    return new Promise<void>((resolve, reject) => {
      transaction.oncomplete = () => resolve();
      transaction.onerror = () => reject(transaction.error);
    });
  }
  
  // 查询优化（使用索引）
  async query(storeName: string, indexName: string, value: any) {
    const transaction = this.db!.transaction([storeName], 'readonly');
    const store = transaction.objectStore(storeName);
    const index = store.index(indexName);
    
    return new Promise<any[]>((resolve, reject) => {
      const request = index.getAll(value);
      request.onsuccess = () => resolve(request.result);
      request.onerror = () => reject(request.error);
    });
  }
}

class ImageOptimizer {
  // 懒加载图片
  static lazyLoadImage(imgElement: HTMLImageElement, src: string) {
    // 使用Intersection Observer API
    const observer = new IntersectionObserver((entries) => {
      entries.forEach(entry => {
        if (entry.isIntersecting) {
          imgElement.src = src;
          observer.unobserve(imgElement);
        }
      });
    }, {
      rootMargin: '50px 0px' // 提前50px加载
    });
    
    observer.observe(imgElement);
  }
  
  // 响应式图片（根据屏幕密度和宽度）
  static getResponsiveImageUrl(baseUrl: string, density: number = 1): string {
    const devicePixelRatio = window.devicePixelRatio || 1;
    const effectiveDensity = Math.min(devicePixelRatio, 3); // 最高3x
    
    // 返回合适的尺寸
    const width = Math.min(window.innerWidth * effectiveDensity, 1200);
    return `${baseUrl}?width=${width}&quality=${density % 100}`;
  }
  
  // 图片压缩
  static async compressImage(file: File, maxWidth: number = 800): Promise<Blob> {
    return new Promise((resolve) => {
      const canvas = document.createElement('canvas');
      const ctx = canvas.getContext('2d');
      const img = new Image();
      
      img.onload = () => {
        // 计算新的尺寸
        let width = img.width;
        let height = img.height;
        
        if (width > maxWidth) {
          const ratio = maxWidth / width;
          width = maxWidth;
          height = height * ratio;
        }
        
        canvas.width = width;
        canvas.height = height;
        
        // 绘制压缩后的图片
        ctx.drawImage(img, 0, 0, width, height);
        
        // 转换为Blob（降低质量）
        canvas.toBlob((blob) => {
          resolve(blob!);
        }, 'image/jpeg', 0.85); // 85%质量
      };
      
      img.src = URL.createObjectURL(file);
    });
  }
}

| 决策点 | 选择 | 理由 | 风险 | 缓解措施 |
|--------|------|------|------|----------|
| 前端框架 | Vue 3 | 团队熟悉，生态成熟 | 生态相对React较小 | 核心功能成熟库，复杂功能自研 |
| 后端框架 | Django | 快速开发，生态完整 | 性能相对较低 | ORM优化，异步处理 |
| 数据库 | PostgreSQL | 功能强大，标准SQL | 扩展成本高 | 分库分表方案准备 |
| 认证方式 | JWT + Refresh | 支持多端，安全 | Token管理复杂 | 引入缓存和撤销机制 |
| 实时功能 | SSE | 简单有效，适用通知场景 | 功能相对有限 | 如需要可升级到WebSocket |
| 任务依赖 | 关系建模+应用计算 | 适中复杂度，性能可控 | 超复杂依赖性能问题 | 如问题突出可引入图数据库 |
| 搜索引擎 | PostgreSQL -> Elasticsearch | 渐进式升级，控制成本 | 迁移可能复杂 | 保留PostgreSQL搜索作为备份 |

### 架构决策验证

通过模型计算验证关键性能指标：

**1. API响应时间预测：**
- 简单查询：50-150ms（单表查询，索引优化）
- 复杂查询：200-800ms（多表连接，缓存优化）
- 超复杂查询：800-2000ms（物化视图，异步计算）

**2. 数据库连接数规划：**
- 预期并发用户：100
- 每用户平均连接数：0.1（连接池）
- 总连接数需求：约10-20个
- 连接池大小：推荐配置20-50个连接

**3. 缓存命中率目标：**
- 热点数据缓存（用户、活动）：90%+
- 查询结果缓存：70-80%
- 会话缓存：95%+
